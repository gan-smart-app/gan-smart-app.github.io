# هوشوارهٔ اختیاری (Claude)

این بخش کاملاً اختیاری است. تا وقتی `VITE_AI_ENDPOINT` در ساخت برنامه خالی است، ماژول `src/core/ai.mjs` هیچ درخواست شبکه‌ای نمی‌فرستد و رابط، هیچ عنصری از هوشواره نشان نمی‌دهد. حتی با نشانی تنظیم‌شده، عناصر هوشواره فقط وقتی دیده می‌شوند که سرور برای حساب مالک `configured: true` برگرداند. با حذف کلید از سرور، این مقدار `false` می‌شود و عناصر دوباره پنهان می‌شوند.

## معماری

```
مرورگر (برنامه) ── ID token فایربیس ──▶ Cloudflare Worker ──▶ Durable Object «AiBudget» ──▶ Anthropic API
```

- **`worker/routes.mjs`**: CORS فقط برای `ALLOWED_ORIGIN`، بررسی توکن، سقف اندازهٔ بدنه.
- **`worker/jwt.mjs`**: بررسی ID token فایربیس با RS256 و کلیدهای عمومی Google (`aud`، `iss`، `exp`، `iat`، `auth_time`، `sub`). فقط `sub == OWNER_UID` پذیرفته می‌شود.
- **`worker/service.mjs`**: یک نمونهٔ واحد Durable Object. شمارش بودجه، کش نتیجه، ادغام درخواست‌های هم‌زمان و لغو در همین‌جا انجام می‌شود.
- **`worker/prompt.mjs`**: دستور ثابت و نسخه‌دار (`p1`)، اعتبارسنجی ساختار ورودی و schema خروجی.
- **`src/core/ai.mjs`**: کلاینت مرورگر؛ قفل درخواست در حال اجرا، کش محلی، لغو و تحلیل خودکار اختیاری.

## مسیرها

| مسیر | کار |
|---|---|
| `GET /status` | `configured`، مدل، کلید پوشانده (`sk-ant-…` و ۴ نویسهٔ آخر)، سقف‌های مؤثر (`limits`) و سقف‌های سخت سرور (`ceilings`)، تعرفه، مصرف امروز/ماه و هزینهٔ تخمینی. کلید کامل هرگز برگردانده نمی‌شود. |
| `POST /analyze` | `{type, payload, detail, promptVersion, requestId?}`. نوع‌ها: `session`، `solve`، `lesson-question`، `plan`. |
| `POST /cancel` | `{requestId}`: لغو درخواست در حال اجرا. |
| `PUT /limits` | فقط مالک. `{dailyRequests?, monthlyRequests?, dailyUsd?, monthlyUsd?}`؛ هر مقدار عدد یا `null` (بازگشت به پیش‌فرض سرور). سقف مؤثر = کمینهٔ مقدار مالک و سقف سخت `wrangler.toml`؛ پس از رابط فقط می‌توان سقف را کم یا به پیش‌فرض برگرداند. پاسخ همان `/status` است. |

خروجی تحلیل: `{summary, points[], suggestions[], algorithms[]}`. هر الگوریتم با `status: 'unverified'` برمی‌گردد. کلاینت فقط نمادگذاری را با `parseAlg` موتور مکعب بررسی می‌کند (`notationValid`) و همیشه `verified: false` می‌گذارد. رابط پیش از ارائهٔ تعاملی، اثر الگوریتم را باید با یک کیس مشخص در موتور مکعب بیازماید.

## قواعد مصرف (در سرور اعمال می‌شوند)

- **مدل**: از متغیر `MODEL`، پیش‌فرض `claude-sonnet-5-5`. هیچ تعویض خودکار مدلی انجام نمی‌شود. پارامتر `fallbacks` ارائه‌دهنده هم عمداً فعال نشده است، چون پس از رد درخواست، آن را روی مدل دیگری (احتمالاً گران‌تر) اجرا می‌کند. رد درخواست با پیام «مدل به این درخواست پاسخ نداد» نمایش داده می‌شود.
- **پارامترها**: `max_tokens` برابر ۸۰۰ برای پاسخ کوتاه و ۲۰۰۰ برای «توضیح مفصل‌تر» که فقط با درخواست کاربر فرستاده می‌شود. `thinking: {type: 'between_tools'}` تفکر اولیه را خاموش می‌کند. `output_config.effort` برابر `low` است و `output_config.format` خروجی JSON ساختاریافته را تعیین می‌کند. `temperature`، `top_p` و `top_k` فرستاده نمی‌شوند.
- **تلاش مجدد**: SDK با `maxRetries: 0` ساخته می‌شود و هیچ تلاش خودکاری وجود ندارد. timeout پیش‌فرض ۴۵ ثانیه است.
- **سقف‌ها**: تعداد درخواست روزانه/ماهانه، بودجهٔ دلاری روزانه/ماهانه، فاصلهٔ حداقل بین درخواست‌ها و سقف اندازهٔ ورودی (پیش‌فرض ۶۰۰۰ نویسه، رشته‌ها حداکثر ۶۰۰ نویسه، عمق ۴). دوره‌ها بر مبنای UTC هستند.
- **رزرو بدبینانه**: پیش از تماس، هزینه با سقف ورودی و سقف خروجی رزرو می‌شود. پس از پاسخ، رزرو با مصرف واقعی پاسخ API جایگزین می‌شود. در خطای قطعی بدون صورتحساب، مثل ۴۰۱، ۴۰۳، ۴۰۴، ۴۰۰، ۴۲۹ و ۵۲۹، رزرو آزاد می‌شود. در timeout، لغو یا قطع شبکه مصرف نامعلوم است و رزرو در بودجه می‌ماند.
- **کش نتیجه**: کلید آن `sha256(نوع + JSON مرتب‌شدهٔ داده + مدل + نسخهٔ دستور + سطح جزئیات)` است. پاسخ ذخیره‌شده با `cached: true` و بدون مصرف تازه برمی‌گردد. کلاینت هم آینهٔ محلی دارد، پس بازکردن دوبارهٔ صفحه تماسی نمی‌سازد. خطاها کش نمی‌شوند.
- **ادغام**: درخواست‌های یکسان هم‌زمان در سرور یک تماس می‌شوند. در کلاینت، کلیک دوباره همان Promise را می‌گیرد.
- **تحلیل خودکار**: فقط با `enabled: true` اجرا می‌شود و برای هر نسخهٔ نهایی جلسه (`sessionId` به‌علاوهٔ هش خلاصه) حداکثر یک بار. اگر شکست بخورد خودکار تکرار نمی‌شود و تلاش بعدی دستی است.
- **Prompt caching ارائه‌دهنده استفاده نشده است.** حداقل طول قابل کش برای Sonnet 5.5 ۵۱۲ توکن است، اما دستور ثابت این سرویس کوتاه‌تر است و برای رسیدن به آن متن اضافه ساخته نشده است. کش نتیجهٔ برنامه با کش ورودی ارائه‌دهنده دو سازوکار جداست.
- **ثبت مصرف**: `input_tokens`، `output_tokens`، `cache_read_input_tokens` و `cache_creation_input_tokens` از پاسخ API ثبت می‌شوند. هزینهٔ نمایش‌داده‌شده تخمینی است و صورتحساب قطعی نیست.
- **رازداری**: کلید فقط secret سرور (`wrangler secret put`) است و از رابط دریافت نمی‌شود. در پاسخ، گزارش (فقط وضعیت و کد خطا) و بستهٔ build نمی‌آید.

## بررسی مستندات رسمی (۲۲ اکتبر ۲۰۲۶)

| مورد | نتیجه | منبع |
|---|---|---|
| شناسهٔ مدل | `claude-sonnet-5-5` در فهرست مدل‌های فعلی است. منتشرشده در ۲۸ سپتامبر ۲۰۲۶ و وضعیت Active. | https://platform.claude.com/docs/en/models/overview ، https://platform.claude.com/docs/en/models/sonnet-5-5/overview |
| تفکر | تفکر Adaptive پیش‌فرض است. `{type:'disabled'}` خطای ۴۰۰ می‌دهد. `between_tools` تفکر اولیه را خاموش می‌کند و فقط در effort ‏`high` یا پایین‌تر مجاز است. | همان صفحهٔ مدل |
| effort | سطح‌ها `low` تا `max` هستند و پیش‌فرض `high` است. | همان صفحهٔ مدل |
| نمونه‌برداری | تنظیم `temperature`، `top_p` یا `top_k` خطای ۴۰۰ می‌دهد. | همان صفحهٔ مدل |
| تعرفه (USD برای هر میلیون توکن) | ورودی ۲، خروجی ۱۰، نوشتن کش ۵دقیقه‌ای ۲٫۵۰، نوشتن کش ۱ساعته ۴، خواندن کش ۰٫۱۰ | https://platform.claude.com/docs/en/about-claude/pricing |
| حداقل کش prompt | ۵۱۲ توکن برای Claude Sonnet 5.5 | https://platform.claude.com/docs/en/build-with-claude/prompt-caching |
| فیلدهای مصرف | `input_tokens`، `output_tokens`، `cache_creation_input_tokens`، `cache_read_input_tokens` و جزئیات `cache_creation` | همان صفحهٔ کش |
| Durable Objects رایگان | روی پلن Free فقط backend SQLite مجاز است. روزانه ۱۰۰٬۰۰۰ درخواست و ۵ گیگابایت فضا. | https://developers.cloudflare.com/durable-objects/platform/pricing/ |

**آزمایش‌نشده‌ها:** دسترسی واقعی حساب شما به این مدل، اعتبار حساب و پذیرفته‌شدن ترکیب `between_tools` با `output_config.format` روی API زنده بررسی نشده‌اند، چون هیچ کلیدی در اختیار نبود و تماس واقعی انجام نشد. پس از استقرار، اولین «بررسی وضعیت» در تنظیمات و یک درخواست دستی کوتاه این‌ها را روشن می‌کند. اگر مدل در دسترس نباشد، خطای «مدل تنظیم‌شده برای این حساب در دسترس نیست» نمایش داده می‌شود و هیچ بخش دیگر برنامه از کار نمی‌افتد.

## راه‌اندازی (کارهایی که شما باید انجام دهید)

۱. **حساب رایگان Cloudflare لازم است.** در https://dash.cloudflare.com/sign-up با ایمیل ثبت‌نام کنید. کارت بانکی برای پلن Free لازم نیست. هیچ حسابی از طرف من ساخته نشده و چیزی مستقر نشده است.
۲. **کلید Anthropic** را از https://platform.claude.com بسازید و اعتبار حساب را بررسی کنید.
۳. در Terminal و از پوشهٔ پروژه:

```bash
cd worker
npx wrangler@4 login
```

۴. در `worker/wrangler.toml` این مقادیر را پر کنید: `ALLOWED_ORIGIN` (نشانی دقیق HTTPS برنامه، بدون `/` آخر)، `FIREBASE_PROJECT_ID` و `OWNER_UID` (UID حساب شما در Firebase Authentication).
۵. کلید را فقط به‌صورت secret وارد کنید. در Terminal پرسیده می‌شود و نمایش داده نمی‌شود:

```bash
npx wrangler@4 secret put ANTHROPIC_API_KEY
```

۶. استقرار:

```bash
npx wrangler@4 deploy
```

۷. نشانی Worker را (مثلاً `https://gan-smart-ai.<subdomain>.workers.dev`) در `VITE_AI_ENDPOINT` فایل `.env` برنامه بگذارید و برنامه را دوباره build کنید.

**تغییر تعرفه یا سقف‌ها:** مقادیر `PRICE_*` و `AI_*` در `wrangler.toml` را عوض کنید و دوباره `deploy` کنید. **حذف کلید:** `npx wrangler@4 secret delete ANTHROPIC_API_KEY`. پس از آن `configured` برابر `false` می‌شود و رابط عناصر هوشواره را پنهان می‌کند.

## آزمون‌ها

`node --test tests/ai.test.mjs tests/ai-worker.test.mjs`: ۲۰ آزمون، همه موفق.

این آزمون‌ها از SDK واقعی با fetch ساختگی استفاده می‌کنند و موارد زیر را پوشش می‌دهند:
- بدون نشانی، صفر درخواست شبکه
- رد توکن جعلی، منقضی، با aud دیگر و توکن غیرمالک
- رد مبدأ بیگانه
- پوشانده‌بودن کلید
- شکل دقیق درخواست به Anthropic
- کش بدون تماس تازه
- ادغام درخواست‌های هم‌زمان
- رد پیش از تماس هنگام پرشدن بودجه یا تعداد
- خطای کلید نامعتبر به فارسی، با آزادشدن رزرو و بدون افشای کلید در پاسخ یا گزارش
- نگاشت ۴۲۹، ۵۲۹، ۴۰۴ و refusal
- اعتبارسنجی ورودی و نسخهٔ دستور
- لغو با حفظ رزرو
- تنظیم سقف‌ها توسط مالک: کاهش، محدودشدن به سقف سخت، بازگشت به پیش‌فرض، اعتبارسنجی، رد غیرمالک و اعمال سقف مؤثر پیش از تماس

`wrangler deploy --dry-run` هم بستهٔ Worker را بدون خطا ساخت. این آزمون‌ها شبیه‌سازی‌اند و تماس واقعی با Anthropic یا Cloudflare نیستند.
